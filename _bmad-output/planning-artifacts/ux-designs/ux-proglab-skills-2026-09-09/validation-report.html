proglab-skills — Rapport de validation UX

_bmad-output/planning-artifacts/ux-designs/ux-proglab-skills-2026-09-09/DESIGN.md · EXPERIENCE.md

La paire DESIGN.md + EXPERIENCE.md est un contrat exploitable en aval : les cinq parcours UJ-1..UJ-5 sont repris verbatim avec protagoniste, étapes numérotées, point culminant et cas limite ; les 22 FR sont tous rattachés à une surface ou déclarés sans interface ; chaque jeton de couleur a son hex en clair et en sombre et toutes les références {…} des deux fichiers se résolvent ; l'ordre canonique des sections est respecté et toutes les décisions du memlog sont placées. Trois points méritent une correction avant que l'architecture et le dev ne s'y appuient : les bordures des badges « À faire » / « Non lisible » référencent {colors.border} (≈ 1,3:1) alors que la forme de bordure est présentée comme porteuse de l'information de statut ; le niveau de titre des Dialog se contredit entre les deux fichiers (h2 / h3) ; et, la direction Aéré venant d'être promue dans mockups/, les liens vers les deux directions rejetées ne résolvent plus tandis que les trois écrans clés en cours de rendu ne sont référencés nulle part. Quelques états (vérification 2FA, invitation d'un email déjà connu, erreur serveur) manquent encore.

La revue accessibilité (WCAG 2.1 AA, sept règles de symfony-proglab-accessibility) déplace le curseur : elle confirme que les spines tiennent leurs règles là où elles sont explicites (statuts icône + libellé, labels réels, :focus-visible, un seul h1, rien derrière le survol, thème sombre conforme partout) mais relève un défaut critique que la rubrique n'a pas vu — la bordure des champs de formulaire à 1,26:1 en clair et 1,18:1 en sombre, seul indice du contour du champ, sur toutes les surfaces à formulaire, connexion comprise (WCAG 1.4.11) — et cinq constats élevés sur ce que les spines promettent sans le spécifier : annonces au lecteur d'écran sous Turbo, autocomplete (1.3.5, critère AA oublié), saisie du code 2FA, sélecteur de langue qui soumet au changement, et muted-foreground / destructive sous 4,5:1 hors d'une carte blanche. Rien n'est structurel : chaque constat se corrige par une ligne de spine ou un jeton. Cinq constats communs aux deux revues ont été fusionnés et portés à la sévérité la plus haute des deux (bordures de badge, muted-foreground hors carte, 2FA, expiration de session, niveaux de titre).

4. Couverture des états

Adéquat

Surfaces parcourues (17 lignes de l'IA) contre State Patterns, Voice and Tone et les flux : chargement (barre Turbo, Frame du Sheet), vides (roadmap, journal, utilisateurs), roadmap partielle, erreurs de champ, ralentissement, compte désactivé (deux points de vue), anonymisé, invitation en attente / expirée, lien expiré, délai 2FA / expiré / nouveau rôle, Lancer inactif / échoué, 403 / 404, session close, langue désactivée en session, thème système, dernière langue active — tous couverts. high

Vérification et enrôlement 2FA : ni états, ni saisie du code spécifiés — États · Accessibilité

EXPERIENCE.md · Information Architecture (Vérification 2FA, Enrôlement 2FA), State Patterns, Voice and Tone, Key Flows › UJ-1 étape 3, Flux 6 étape 5
Aucun état : code erroné, code email expiré / « Renvoyer un code », utilisation d'un code de secours, échec de la vérification à l'enrôlement, épuisement des codes de secours. La revue accessibilité ajoute que la saisie du second facteur n'est spécifiée nulle part : ni le type de champ (un seul <input> ou six cases), ni inputmode="numeric", ni le label, ni l'association de l'erreur « code incorrect », ni le chemin « utiliser un code de secours », ni, pour le code par email, sa durée de validité et le bouton « Renvoyer ». Le composant « InputOTP » à six cases, tentant dans un kit shadcn, est notoirement hostile aux lecteurs d'écran (six champs sans label, focus qui saute).
Correction : trois lignes de State Patterns + les phrases correspondantes en Voice and Tone (« Code incorrect. Vérifiez l'heure de votre téléphone ou utilisez un code de secours. ») ; un seul champ texte, label visible « Code à 6 chiffres de votre application », inputmode="numeric" autocomplete="one-time-code" pattern="[0-9]{6}", espaces tolérés ; lien « Je n'ai pas accès à mon application — utiliser un code de secours » vers un champ distinct ; pour le code par email : « valable 10 minutes » + bouton « Renvoyer un code » ; erreur en aria-invalid + aria-describedby comme les autres champs.

Durée de session et expiration par inactivité non spécifiées — États · Accessibilité

Revue accessibilité (WCAG 2.1 AA)

review-accessibility.md

Lentille : WCAG 2.1 AA, lue à travers les sept règles de symfony-proglab-accessibility. Sources : DESIGN.md, EXPERIENCE.md, .memlog.md, .working/direction-aere.html (CSS et DOM réels). Les ratios sont recalculés depuis les hex du frontmatter de DESIGN.md (formule WCAG), pas repris des annotations.

Ce qui fera échouer un audit se trouve dans ce que les spines promettent sans le spécifier — annonces au lecteur d'écran sous Turbo, autocomplete (1.3.5, critère AA oublié), saisie du code 2FA, sélecteur de langue qui soumet au changement — et dans deux paires de contraste que le thème neutre shadcn rate hors d'une carte blanche : la bordure des champs (1,26:1) et muted-foreground / destructive sur le fond de page (4,35:1 et 4,38:1). Rien n'est structurel : chaque constat se corrige par une ligne de spine ou un jeton.

Fusionnés avec la rubrique (voir les sections correspondantes) : bordures de statut et rail de Progress (§2, élevé), muted-foreground / destructive hors carte (§2, élevé), saisie et états du second facteur (§4, élevé), durée de session (§4, moyen), niveaux de titre (§7, moyen).

Ce qui est solide : la règle 1 est tenue jusque dans les détails (chaque statut est icône + libellé, l'origine d'une permission est un Badge libellé, l'erreur de champ est bordure + icône + texte + aria-invalid + aria-describedby, le test « niveaux de gris » est nommé comme critère) ; le thème sombre passe intégralement (texte secondaire 7,1–10,3:1 sur carte, destructive-dark 6,2–6,9:1, anneau 3,2–4,2:1) ; focus :focus-visible conservé partout, retour du focus au déclencheur après Sheet / Dialog / tiroir, Échap ferme toujours la couche la plus haute, une seule couche flottante à la fois ; pas de toast qui disparaît, pas d'action au survol, pas de défilement infini, pas de raccourci inventé, pas de capitales forcées ; secours sans JavaScript spécifié (Accordion en <details>, Sheet et Dialog en pages complètes, formulaires POST + redirection) ; messages d'erreur qui disent quoi faire ensuite, messages génériques qui ne révèlent pas l'existence d'un compte, Dialog destructif qui nomme la personne et la conséquence ; corps à 15 px, chiffres tabulaires, largeur de lecture bornée, aria-current="page" sur la navigation, lang qui suit la langue d'interface, Progress toujours doublée d'une phrase ; la dette de l'anneau de focus est consignée avec sa valeur et son déclencheur de revérification (rebranding) — c'est exactement ainsi qu'un écart doit être documenté.
