- (capability) CAP-12 (FR-12) Audit explicite des actions métier nommées, déclaré depuis la couche service avec code stable et libellé traduisible.

- (capability) CAP-14 (FR-14) Lecture de la roadmap depuis les fichiers BMAD embarqués, sans base intermédiaire, tolérante aux fichiers absents ou mal formés.

- (capability) CAP-16 (FR-16) Lancement d'une tâche prête depuis la roadmap, en environnement de développement seulement, par démarrage d'un processus local détaché.

- (capability) CAP-20 (FR-20) Anonymisation irréversible d'un utilisateur désactivé, satisfaisant le droit à l'effacement sans perdre l'historique.
- (capability) CAP-21 (FR-21) Gestion de son profil : langue, mot de passe, réenrôlement de la 2FA.
- (capability) CAP-22 (FR-22) Activation et désactivation d'une langue du dérivé depuis l'interface, la dernière langue active ne pouvant être retirée.
- (constraint) Symfony 7.4 LTS sur PHP 8.5 ; aucune dépendance exigeant Symfony 8 n'entre dans le socle (AD-1) — exclut damienharper/auditor-bundle 7.x.
- (constraint) Standard proglab (symfony-proglab-*) intégral pour les couches, la sécurité et la qualité ; planification et exécution pilotées par BMAD.
- (constraint) Deux racines src/Core et src/Module/<Nom> ; Core/Contract est la seule porte ; un dérivé n'édite aucun fichier de src/Core/ ni de config/ (AD-2, AD-13).
- (constraint) Les fichiers BMAD sont un contrat d'entrée en lecture seule : l'application ne les écrit jamais, seul var/ est inscriptible (AD-10).
- (constraint) Un ERP par client, déployé séparément ; le socle se clone et diverge, son code n'est pas resynchronisé, mais un dérivé livré est maintenu en version depuis le socle (AD-1).
- (constraint) API écrite à la main, sans API Platform, tant que le contrat reste réduit ; jeton opaque révocable, jamais de JWT sans état (AD-5).
- (constraint) Journal d'audit en ajout seul, magasin unique ; seule exception nommée, l'anonymisation réécrit les entrées portant le nom du compte (AD-12).
- (constraint) Tout chemin fonctionne en pleine page sans JavaScript ; Turbo et Stimulus n'ajoutent que le confort (AD-17).
- (constraint) Plancher WCAG 2.1 de symfony-proglab-accessibility, vérifié par test automatisé en CI, jamais par relecture (AD-16, AD-22).
- (constraint) Aucun service externe payant : l'envoi d'email passe par le SMTP du client ou de l'équipe.
- (constraint) Budget de performance : les écrans du socle répondent sous la seconde au p95 pour un dérivé de taille courante ; le journal d'audit est paginé (AD-20).
- (constraint) Le socle reste interne : ni vendu, ni ouvert ; il n'est pas le produit vendu au client.
- (constraint) Aucun module commun n'entre dans le socle tant que deux dérivés ne l'ont pas réclamé (contre-métrique SM-C1).
- (constraint) Les 22 décisions AD-1..AD-22 de l'ARCHITECTURE-SPINE sont contraignantes au même titre que celles listées ici ; le spine en porte le détail.
